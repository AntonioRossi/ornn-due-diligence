## Inference flow

- Each Host runs at least two nodes:
  - **Network Node** — Chain Node (blockchain) + API Node (user requests)
  - **One or more ML Nodes** — perform LLM inferences (multi-server allowed)
- Roles are **dynamic**, not predefined or on-chain:
  - Transfer Agent (TA), Executor, Validator are operational functions assumed
    when processing a request.
- Inference flow:
  1. Client (Developer) picks a random Host from active-participants list — that
     Host becomes the Transfer Agent (TA).
  2. TA picks a random Executor among other active Hosts; records inference input
     on-chain in parallel.
  3. Executor's API node hands work to one of its ML Nodes; inference begins
     immediately.
  4. ML Node returns output to Executor's API node.
  5. Executor sends output back to TA; Executor's Chain Node records validation
     artifact on-chain.
  6. TA returns output to Client; TA's Chain Node records it on-chain.
- Computation is **off-chain**; only validation artifacts and transactions are
  on-chain.
- Validation is **post-hoc**, in parallel with subsequent inferences. If an
  Executor is caught cheating, they lose rewards for the whole epoch and the
  client is notified and refunded.

## Proof of Compute (PoC) consensus

- Described as a novel consensus mechanism intended to combine PoW's
  weight/work/reward alignment with productive utility (concentrating proving
  into a short "Sprint" window).
- Contrast with PoS: "Unlike PoS, which aligns weight with the staked coins."
- Contrast with PoW: "Unlike Proof of Work, Proof of Compute concentrates the
  proving part (Sprint) in a short limited time window, freeing the rest of the
  time for useful work."

## Epoch mechanics

- **Epoch length:** 17,280 blocks (~24 hours).
- All Sprints begin **simultaneously** across Hosts, coordinated via a random
  seed generated by all Hosts with voting power. No minority pre-computation
  advantage.
- Sprint is short by design; majority of the epoch reserved for productive
  inference/training.
- Epoch end: auto-claim rewards for epoch N. New Sprint determines weights for
  N+1.

## Reward claim and burn mechanics

- If reward for epoch N not auto-claimed, each Host's API node retries every
  30 minutes during epoch N+1 using the seed signed at start of epoch N.
- Host must remain online and pass verification; otherwise reward is lost.
- **Unclaimed rewards from epoch N are permanently BURNED as soon as epoch N+2
  begins.**
- During the claim window, Hosts can submit overdue inference-validation
  artifacts as a last chance to execute pending validations.
